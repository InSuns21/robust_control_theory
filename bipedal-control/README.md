# 二足歩行制御入門：なぜ「倒れずに歩く」は難しいのか

この教材は、ヒューマノイドの二足歩行制御を「いきなり全身多剛体系」から始めず、
最小モデルから段階的に理解するための実習資料です。

- **第1段階**：倒立振子 — 立っているだけで不安定
- **第2段階**：PD フィードバック — 小さな傾きなら足首トルクで戻せる
- **第3段階**：支持領域と ZMP — 足裏には有限の大きさがある
- **第4段階**：線形倒立振子モデル（LIPM） — 重心と ZMP の関係を線形化する
- **第5段階**：Capture Point — 大きく崩れたら「足を出す」
- **第6段階**：歩行 — 立位安定化ではなく、支持脚を意図的に切り替え続ける

ブラウザ実験は [`docs/bipedal-control/`](../docs/bipedal-control/) にあります。

---

## 1. なぜ二足歩行は難しいのか

机や四輪車は、静止しているだけなら重心投影が支持領域の中にありやすく、受動的に安定です。
一方、二足歩行では片足立ちの時間が長く、支持領域は足裏 1 枚まで縮みます。

さらに歩行中は、

1. 片足支持と両足支持が切り替わる
2. 足が地面から離れる／接触するという離散イベントがある
3. 摩擦・関節トルク・足裏接触には上限がある
4. センサ誤差と遅延がある
5. 上半身・腕・遊脚も運動して重心や角運動量を変える

ため、単なる「姿勢制御」ではありません。

二足歩行は、**連続時間の力学 + 接触状態の離散切替 + 制約付き最適化**が同時に現れる問題です。

---

## 2. 最小モデル：倒立振子

質量 \(m\) の点質量が、長さ \(l\) の質量のない棒の先端にあるとします。
鉛直上向きからの角度を \(\theta\) とすると、

\[
\ddot{\theta}
=
\frac{g}{l}\sin\theta
+
\frac{u}{m l^2}
\]

です。

重要なのは符号です。小角度なら \(\sin\theta \approx \theta\) なので、

\[
\ddot{\theta}
\approx
\frac{g}{l}\theta
+
\frac{u}{m l^2}.
\]

制御入力 \(u=0\) では

\[
\ddot{\theta}\approx \frac{g}{l}\theta
\]

となり、傾きが増える方向へ加速度が出ます。
つまり鉛直上向き平衡点は**不安定平衡点**です。

### 実験

ブラウザ実験の「倒立振子」で制御を OFF にし、初期角度を 2〜5 度与えてください。
わずかな傾きでも時間とともに増幅します。

---

## 3. PD フィードバックで立たせる

最も単純には

\[
u
=
- m l^2
\left(
K_p\theta + K_d\dot{\theta}
\right)
\]

とします。

すると小角度近似では

\[
\ddot{\theta}
=
\left(
\frac{g}{l}-K_p
\right)\theta
-
K_d\dot{\theta}.
\]

したがって、少なくとも局所的には

\[
K_p > \frac{g}{l},
\qquad
K_d > 0
\]

なら、重力による不安定化を打ち消せます。

ただし現実には、足首トルクには上限があります。
いくらゲインを上げても「無限の力」は出ません。

この制約が、次の ZMP / 支持領域につながります。

---

## 4. 支持領域と ZMP

足裏が地面に接触しているとき、床反力の合力は足裏のどこかを通ります。
この作用点を、簡略化した教材では ZMP（Zero-Moment Point）として扱います。

足裏の長さを \(2b\)、足中心を \(p_f\) とすると、ZMP は概ね

\[
p \in [p_f-b,\;p_f+b]
\]

という制約を受けます。

必要な ZMP がこの範囲を超えると、足裏全体で床を押し続けることができません。
かかとやつま先を支点に回転し始め、足首戦略だけでは回復できなくなります。

つまり、**制御器が要求する入力が物理的に実現可能か**が重要です。

---

## 5. 線形倒立振子モデル（LIPM）

重心の高さを一定 \(z_c\) と仮定し、角運動量の効果を簡略化すると、
水平重心位置 \(x\) と ZMP \(p\) の関係は

\[
\ddot{x}
=
\omega^2(x-p),
\qquad
\omega = \sqrt{\frac{g}{z_c}}
\]

と書けます。

ここでも本質は同じです。

- \(x=p\) なら水平加速度は 0
- \(x>p\) なら右へ加速
- \(x<p\) なら左へ加速

したがって重心が足より前に出れば、放置するとさらに前へ倒れます。

### 目標加速度から ZMP を逆算する

目標重心位置 \(x_r\) に戻すため

\[
\ddot{x}_{\rm des}
=
-K_p(x-x_r)-K_d\dot{x}
\]

と置きます。

LIPM の式から必要 ZMP は

\[
p_{\rm req}
=
x
-
\frac{\ddot{x}_{\rm des}}{\omega^2}
=
x
+
\frac{
K_p(x-x_r)+K_d\dot{x}
}{\omega^2}.
\]

しかし実際に使える ZMP は足裏内だけなので、

\[
p
=
\operatorname{clip}
\left(
p_{\rm req},
p_f-b,
p_f+b
\right)
\]

となります。

ここで飽和が起きると、「制御則は正しいのに倒れる」という現象が発生します。

---

## 6. Capture Point：倒れそうなら足を出す

LIPM に対して

\[
\xi
=
x+\frac{\dot{x}}{\omega}
\]

を考えます。これが Capture Point の基本形です。

直感的には、**今の重心位置と速度を考えたとき、そこへ足を置けば倒れ込みを止められる位置**です。

重心が右へ高速で移動していれば、現在の重心よりさらに右へ足を出す必要があります。
つまり人間が押されたときに自然に行う「一歩出す」が数式として現れます。

### 足首戦略とステップ戦略

- Capture Point が支持領域内  
  → 足首トルク / ZMP 移動で戻せる可能性が高い
- Capture Point が支持領域外  
  → 現在の足裏だけでは回復困難
- 届く範囲に次の足を置ける  
  → ステップして新しい支持領域を作る

これが二足歩行制御の重要な考え方です。

---

## 7. 「立つ」と「歩く」は何が違うか

立位安定化は、同じ支持領域の中へ状態を戻す問題です。

歩行は逆に、

1. 次の支持位置を決める
2. 遊脚をそこへ運ぶ
3. 接地する
4. 支持脚を切り替える
5. 次の一歩を再計算する

ことを繰り返します。

つまり歩行とは、**不安定な倒立振子を完全に止めるのではなく、倒れ込みを次の足で捕まえ続ける運動**と見ることができます。

## 8. ブラウザ実験で確認する順番

### 実験 A：制御なし

- 倒立振子の制御を OFF
- 初期角度 3°
- 外乱 0

観察：角度が指数的に増える。

### 実験 B：PD 制御

- 制御 ON
- \(K_p\) を徐々に増加
- \(K_d\) も増加

観察：小外乱なら復帰する。

### 実験 C：大きな押し

LIPM 実験で Push を押す。

観察：

- 必要 ZMP が足裏端へ張り付く
- Capture Point が支持領域外へ出る
- 足を出さない設定では転倒する

### 実験 D：自動ステップ

Auto step を ON にして同じ Push を与える。

観察：

- Capture Point 付近へ遊脚を移す
- 支持領域が更新される
- 回復可能な範囲なら転倒せずに済む

### 実験 E：歩行

Walk を ON にして目標速度を変える。

観察：

- 重心を完全に静止させていない
- 左右の支持脚を切り替えながら進む
- 歩幅上限を超える速度では破綻する

## 9. この教材で省略しているもの

この実装は理解用の低次元モデルです。実機ではさらに必要です。

- 多剛体系運動方程式
- 関節角の逆運動学
- 逆動力学
- 接触力最適化
- 摩擦円錐
- 関節トルク・速度・可動域制約
- IMU / エンコーダ / 力覚センサの状態推定
- 遅延、ノイズ、モデル誤差
- 遊脚軌道生成
- 角運動量制御
- Model Predictive Control
- Whole-Body Control
- 転倒検知と転倒動作
- 不整地認識と足場計画

LIPM や Capture Point は「完成形」ではなく、これらを理解するための圧縮モデルです。
